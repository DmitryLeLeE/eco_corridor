# Валидация

Здесь описано, **что именно проверено, как и с каким результатом**, а также что проверено не было. Проверка бывает разных видов; важно не смешивать их: прохождение тестов подтверждает, что код делает то, что задумано, но не доказывает, что модель верна для реальных ландшафтов.

## 1. Уровни проверки

| Уровень | Вопрос | Статус |
|---|---|---|
| Верификация кода | Реализован ли алгоритм так, как описан? | <span class="status-ok">выполнена</span> — 85 автоматических тестов с заранее известными ответами и сверкой с независимой эталонной реализацией (2.2б) |
| Сверка с первоисточниками | Совпадают ли формулы с определениями индексов? | <span class="status-part">частично</span>: библиографические записи сверены по каталогам издателей (2026-11-11), содержание — по аннотациям; полные тексты статей не перечитывались ([«Источники»](references.html)) |
| Сверка с эталонными программами | Совпадают ли числа с Conefor, Graphab, Linkage Mapper? | <span class="status-part">частично</span>: с Conefor 2.6 сверены PC, IIC и ECA на игрушечном примере и на демо (разница ≤ 5·10⁻⁷, раздел 6.1); Graphab, Linkage Mapper и реальная территория не сверялись |

## 2. Автоматические тесты

Запуск: `python -m pytest -q` (≈10 с). Тесты лежат в `tests/`.

### 2.0 Теория цепей (`test_circuit.py`)

Аналитические цепи (лестница из параллельных цепочек, две полосы с разной проводимостью, единичный ток через сечение), независимая плотная реализация на случайном ландшафте при 4 и 8 соседях (эффективное сопротивление и накопленный ток), симметрия и неравенство треугольника, параллельный маршрут вдвое снижает сопротивление, барьер с одним проходом концентрирует ток. Подробности и ограничения — [Методика](methodology.html), раздел 4.1. С Circuitscape не сравнивалось.

### 2.1 Пути наименьшей стоимости (`test_costpath.py`)

| Проверка | Ожидаемый результат (аналитический) |
|---|---|
| Прямая линия в однородной среде | стоимость = длина × R |
| Ортогональный шаг между ячейками с разными R | среднее двух значений |
| Диагональный шаг в однородной среде | длина диагонали × R |
| Диагональный проход сквозь однопиксельный барьер (8 и 16 соседей) | стоимость много выше, чем при пересечении «в лоб»: нет «протечки» |
| Диагональный проход не дешевле ортогонального на порядки | отношение ограничено |
| Анизотропия в однородной среде | удлинение ≤ 1,0824 (8 соседей) и ≤ 1,0276 (16) — значения 1/cos половины наибольшего углового промежутка |
| Недопустимые ячейки (NaN, ≤ 0) | непроходимы |

### 2.2 Индексы связности (`test_fragmentation.py`)

| Проверка | Ожидаемый результат |
|---|---|
| MESH и деление нормируются на площадь ландшафта | сверка с ручным расчётом |
| IIC для двух патчей | учтён внутрипатчевый член, значение — по формуле |
| IIC учитывает цепочки патчей | пары, недостижимые напрямую, связаны через промежуточные |
| PC — максимум произведения вероятностей | промежуточный патч повышает p* выше прямого значения |
| Потеря местообитания не повышает PC и IIC | при фиксированном A<sub>L</sub> индексы не растут |
| dPC патча-«моста» | значение велико |
| Полностью связный ландшафт | PC = 1 |
| Нет местообитаний | результат помечен как недоступный |

Шесть из восьми этих тестов **падали** на коде до аудита; это подтверждает, что исправленные дефекты были реальными ([Аудит](review.html)).

### 2.2а PC и ECA по стоимости (`test_fragmentation.py`)

| Проверка | Ожидаемый результат (аналитический) |
|---|---|
| Однородная поверхность R = R<sub>ref</sub> | PC по стоимости совпадает с PC на прямых расстояниях, ECA тоже |
| Матрица вдвое сопротивляется, патчи — на уровне R<sub>ref</sub> | эффективное расстояние = 2 × зазор (стоимость пути g + 1 шагов: два крайних по 15, остальные по 20, минус ячейка); PC по стоимости совпадает с формулой (допуск — округление вывода до 6 знаков); PC на прямых расстояниях не меняется |
| Почти непроходимая полоса поперёк зазора | PC и ECA по стоимости падают, PC на прямых расстояниях не меняется |
| Граф не передан | PC по стоимости не вычисляется (`None`) |
| Полностью связный ландшафт | PC по стоимости = 1 |

### 2.2б Сверка с эталонной реализацией (`test_reference.py`)

Модуль `ecocorridor/reference.py` пересчитывает те же величины другим, более простым и медленным способом: максимум произведения вероятностей — Дейкстра по произведениям (`heapq`), а не по −ln p в scipy; число переходов в IIC — `networkx`; расстояние «край — край» — перебор всех пар ячеек с точным зазором между квадратами; стоимость пути — граф `networkx`, построенный по рёбрам. Определения общие с боевым кодом (Saura & Pascual-Hortal 2007), поэтому совпадение показывает, что они реализованы как написаны. Оно не заменяет сравнения с Conefor и Graphab: эталон — не их код.

| Проверка | Результат |
|---|---|
| PC, IIC, ECA на 6 случайных ландшафтах (36 × 36 ячеек по 100 м, d₀ = 800 м), один и тот же граф участков | совпадают в пределах округления вывода (\|ΔPC\| < 6·10⁻⁷) |
| Расстояния между участками против перебора всех пар ячеек | совпадают до 10⁻⁶ м, наборы пар одинаковы |
| Два одноклеточных участка со сдвигом (3, 3) ячейки | расстояние √(2² + 2²)·h, а не 3√2·h − h |
| Отсечение пар с p < 0,01 в PC (d₀ = 200 м, часть пар заведомо дальше порога) | изменение PC < 1 % (в трёх ландшафтах — ниже точности вычисления) |
| Стоимости путей, PC и ECA по стоимости против графа `networkx` на 3 случайных поверхностях сопротивления (28 × 28) | наборы пар и значения совпадают (относительная разница < 10⁻⁹) |
| Экспорт для Conefor | файлы согласованы с графом участков; игрушечный пример совпадает с расчётом вручную |

**Что нашла сверка.** До неё расстояние между участками считалось как «расстояние между центрами ближайших граничных ячеек минус размер ячейки». Для зазора вдоль осей это точно, для диагонального сдвига оно завышено до (√2 − 1)·h (41 м при h = 100 м, в среднем около 23 м). PC получался ниже точного на 1–4 % (6 тестовых ландшафтов: 3,4; 1,1; 2,2; 3,0; 3,3 и 4,1 % при h/d₀ = 1/8); на демо PC изменился с 0,482 до 0,485. Исправлено: для ближайшей по центрам пары перебираются все пары в пределах (√2 − 1)·h и берётся точный зазор между квадратами. MESH и IIC на демо не изменились в третьем знаке, PC по стоимости исправление не затрагивает (он считается по стоимости пути). В [аудите](review.html) расстояние называлось «точным»; это было верно только для зазоров вдоль осей.

**Что остаётся.** Поправка на одну ячейку в эффективном расстоянии (раздел 5.5 методики) приближённая для диагональных зазоров: проверена реализация определения, не само определение.

### 2.3 Загрузчик территорий (`test_online.py`)

Тесты работают без сети: тайлы WorldCover (3°) и Copernicus DEM (1°) генерируются на диске для синтетической территории, а Overpass подменяется образцом ответа.

| Область | Что проверяется |
|---|---|
| Именование тайлов | схема имён WorldCover и Copernicus, в том числе для отрицательных координат; тайлы не захватывают соседей на границах |
| План кадра | выбор зоны UTM (включая южное полушарие), автоматическое разрешение, расширение малых и обрезка больших кадров, ограничение числа ячеек, отказ на некорректных входных данных |
| Мозаика | кадр на стыке двух тайлов собирается без разрывов; нет ни одного тайла — это ошибка, а не «море» |
| Рельеф | уклон на синтетической «рампе» совпадает с аналитическим (±0,1°); резервный переход GLO-30 → GLO-90 → плоский с предупреждением |
| OSM | запрос корректен; дороги отфильтрованы (туннели исключены, `_link` объединены, мосты помечены); ООПТ: мультиполигон с «дыркой», дубликат внутри другой ООПТ удалён, слишком мелкие, класс IUCN V и ООПТ вне кадра отброшены; населённые пункты отсортированы по населению |
| Впекание дорог | дороги попадают в растр; мост пересекает воду, обычная дорога — нет |
| Оркестрация | проект собирается, кэшируется, повторная загрузка идёт с диска без обращений к сети; весь расчёт проходит на загруженном проекте; резервный выбор ядер; предупреждения |
| API | поиск → план → фоновая загрузка → опрос → открытие проекта → расчёт → экспорт; читаемые ошибки |

### 2.4 Прочие

`test_api.py` проверяет, что расчётные эндпоинты используют проект результата (а не глобальный), что урбанизация не повышает связность, что пресет «лес» уменьшает местообитание, и что экспорт работает.

Интерфейс проверялся прогоном в браузере (Chrome, headless) на синтетической территории: поиск, план, загрузка, расчёт, переключение сценариев, возврат к демо — без ошибок в консоли. Эта проверка не входит в автоматические тесты.

### 2.5 Калибровка сопротивлений (`test_calibration.py`)

Оценщики проверены на симулированных животных с известным ответом: ландшафт 140 × 140 ячеек, три класса (лес, луг, пашня) с истинным относительным сопротивлением 1 : 3 : 8, вероятность выбора обратно пропорциональна сопротивлению.

| Метод | Данные | Оценка (лес : луг : пашня) | 95 % интервал, луг / пашня |
|---|---|---|---|
| RSF | 4000 точек, 10 фоновых на каждую | 1 : 3,13 : 8,64 | 2,89–3,38 / 7,64–9,78 |
| SSF | 30 животных × 120 шагов, 30 случайных шагов на наблюдаемый | 1 : 2,95 : 8,20 | 2,62–3,32 / 6,18–10,89 (по модели) |

В 30 независимых повторах RSF (по 1500 точек) интервалы накрыли истинные значения обоих классов одновременно в 28 случаях (тест требует не менее 23: для двух классов при номинальных 95 % ожидается около 90 %). Тесты также проверяют, что редкий класс (менее 10 наблюдений) не оценивается, сохраняет прежнее сопротивление и помечается; что откалиброванное сопротивление привязано к прежнему значению самого предпочитаемого класса; что точки вне кадра отбрасываются; что скрипт `scripts/calibrate.py` работает и записывает откалиброванную копию территории.

Это проверка кода, а не метода для конкретного вида: в симуляции нет ошибки позиционирования GPS, нет автокорреляции шагов (она есть у реальных треков, поэтому для SSF предусмотрен бутстреп по животным), класс землепокрова известен точно, а выбор зависит только от класса.

## 3. Анализ чувствительности (демо «Синий Бор»)

Сопротивления классов умножаются на exp(N(0; σ)), веса поверхности — на U(1 − s; 1 + s); для каждого розыгрыша заново считается весь конвейер. Скрипт: `scripts/sensitivity.py`; сырые результаты: [`data/sensitivity_demo.json`](https://github.com/DmitryLeLeE/eco_corridor/blob/main/docs/data/sensitivity_demo.json).

{{SENSITIVITY_TABLE}}

**Что из этого следует.**

* **Положение коридоров чувствительно к сопротивлениям.** Среднее пересечение полос коридора с базовым вариантом ≈ 0,45: две «разумные» таблицы сопротивлений дают заметно разные трассы. Конкретную линию на карте нельзя считать устойчивым результатом без калибровки.
* **Топология остова устойчивее.** Набор связей остова почти не менялся (но на демо кандидаты — все пары из четырёх ядер, поэтому набор связей совпадает тривиально).
* **PC, IIC и MESH на прямых расстояниях не меняются** — потому что не зависят от сопротивления по построению ([Методика](methodology.html), раздел 5.5). По ним порядок сценариев не говорит об устойчивости.
* **PC по стоимости зависит от сопротивления.** Его коэффициент вариации в прогонах мал (≈ 3 %), знаки и порядок эффектов сценариев сохраняются во всех прогонах (urban < road < restore), а величина эффекта «Восстановления» заметно меняется (+14…+28 %).

**Чувствительность к опорному сопротивлению R<sub>ref</sub>** (демо, базовые параметры; Δ относительно базового сценария при том же R<sub>ref</sub>):

| R<sub>ref</sub> | PC по стоимости, базовый | Δ урбанизация, % | Δ дорога, % | Δ восстановление, % |
|---|---|---|---|---|
| 5 | 0,161 | −1,83 | −0,64 | +7,5 |
| 10 (по умолчанию) | 0,172 | −1,81 | −0,63 | +19,8 |
| 20 | 0,205 | −1,75 | −0,61 | +32,8 |
| 40 | 0,269 | −1,67 | −0,56 | +32,0 |

Знаки и порядок эффектов сценариев от R<sub>ref</sub> не зависят; **абсолютные значения индекса и размер эффекта восстановления — зависят сильно**. Поэтому PC по стоимости пригоден для сравнения сценариев при фиксированном R<sub>ref</sub>, а не для абсолютных оценок.
* Число прогонов невелико: это оценка порядка величины, а не доверительные интервалы. Для публикации следует повышать число прогонов и варьировать также d₀, α<sub>ref</sub>, D<sub>r</sub>, D<sub>u</sub> и выбор местообитания.

## 5. Чего не доказывают эти проверки

* Что выбранные сопротивления верны для какого-либо вида.
* Что слой тока совпадает с Circuitscape: проверены только аналитические цепи и независимая плотная реализация той же модели.
* Что построенные коридоры используются животными.
* Что индексы согласуются с Graphab и с Conefor на реальных территориях: с Conefor 2.6 сверены игрушечный пример и демо (раздел 6.1), с Graphab сравнения не было; **на реальной территории (например, загруженной по названию) сравнение стоит повторить** до использования результатов в публикациях.
* Что откалиброванные по точкам сопротивления описывают перемещение, а не выбор местообитания (Zeller et al. 2012): калибровка по присутствиям отвечает на другой вопрос.
* Что загрузчик справится с любой территорией мира: краевые случаи (антимеридиан, полярные районы выше 84° ш., острова без ООПТ) ограничены или не проверены.

## 6. Что выполняет пользователь: сверка с Conefor и калибровка

Эти два шага требуют внешних программ и данных, которых нет в среде разработки (Conefor и Graphab недоступны для скачивания, данных о животных нет). Инструменты подготовлены и проверены на синтетике; результат сверки и калибровки появится только после запуска на реальных данных.

### 6.1 Сверка с Conefor (Saura & Torné 2009)

1. **Игрушечный пример** — подтверждает, что настройки Conefor воспроизводят определения пакета:

   ```
   python scripts/conefor_check.py toy out/toy
   ```

   В `out/toy` лежат `nodes.txt`, `distances.txt`, `conefor_settings.txt` (настройки Conefor) и `expected.json` (ожидаемые значения: четыре участка, ответ известен). Запустите Conefor (2.6: `Conefor26.exe`, установка не нужна) на этих файлах и сравните. В Conefor 2.6 ECA выдаётся как EC(PC) (`--eca`); в версии 2.2 его нет, передаётся числитель PCnum (`--pcnum`, ECA = √PCnum):

   ```
   python scripts/conefor_check.py compare out/toy/expected.json --pc <PC> --iic <IIC> --eca <EC(PC)>
   ```

   Формат файлов и настройки сверены с руководством Conefor Sensinode 2.2 (разделы 4.2, 5.2, 5.3, 6.2.3, 6.3): каждая пара узлов один раз, без заголовков, обе таблицы заканчиваются пустой строкой, формат связей — PARTIAL, тип связей — Distances, A<sub>L</sub> вводится вручную, связь в IIC при расстоянии не больше порога, p = exp(−k·d) с k, подобранным под заданную пару «расстояние — вероятность». ### 6.2 Калибровка сопротивлений по данным о животных

Нужны точки присутствия (CSV с колонками `lon`, `lat`) или GPS-треки (`id`, `lon`, `lat`, строки одного животного в порядке времени).

```
python scripts/calibrate.py rsf points.csv --cached ta329e77086 --out calibration.json
python scripts/calibrate.py ssf tracks.csv --cached ta329e77086 --boot 200 --save-project
```

Скрипт печатает по каждому классу число наблюдений, коэффициент β, относительное сопротивление с 95 %-м интервалом, прежнее и новое значение. С `--save-project` откалиброванная копия территории попадает в кэш и видна в списке территорий приложения рядом с исходной.

Как читать результат:

* Оценивается **выбор** землепокрова: сопротивление класса — величина, обратная относительной частоте его использования (самый предпочитаемый класс получает прежнее сопротивление, остальные — пропорционально). Выбор местообитания и стоимость перемещения — не одно и то же (Zeller et al. 2012); по точкам присутствия движение вообще не наблюдается, поэтому предпочтителен SSF по трекам (Fortin et al. 2005; сравнение подходов — Zeller et al. 2015).
* Классы с числом наблюдений меньше порога (`--min-used`, 10) не оцениваются и сохраняют прежнее значение; в таблице они помечены.
* Контраст ограничен `--max-ratio` (100): класс, который не используется совсем, иначе получил бы бесконечное сопротивление.
* **Не калибруются** веса уклона, дорог и застройки, опорное сопротивление R<sub>ref</sub> и расстояние расселения d₀. Для R<sub>ref</sub> есть соглашение, не калибровка: `calibration.reference_resistance(resistance, habitat_mask)` возвращает медианное сопротивление местообитаний, то есть масштаб, при котором d₀ — расстояние «по местообитанию».
* В SSF случайные шаги берутся с равномерным направлением и длинами из пула наблюдаемых шагов (персистентность поворота не моделируется). Шаги одного животного зависимы; при 5 и более животных используйте `--boot`, чтобы погрешности считались бутстрепом по животным.

После калибровки повторите анализ чувствительности (`scripts/sensitivity.py --cached <id>`) и таблицу по R<sub>ref</sub> (`scripts/rref_sweep.py --cached <id>`) для откалиброванной копии.
