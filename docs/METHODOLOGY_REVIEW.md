# Проверка методики EcoCorridor на научную состоятельность

Дата проверки: ноябрь 2026. Объект: `src/ecocorridor` (костпат, коридорная сеть, индексы фрагментации, сценарии) и текст методики в интерфейсе и отчёте.

**Как проверяли.** Каждое подозрение сначала воспроизводилось аналитическим тестом с заранее известным ответом (прямая линия, барьер, два патча на известном расстоянии), и только потом исправлялось. Тесты лежат в `tests/` и падают на старом коде (6 из 8 тестов `test_fragmentation.py`).

**Чего проверка не доказывает.** Сравнение с Conefor 2.6 выполнено только для PC, IIC и ECA на игрушечном примере и на демо (разница ≤ 5·10⁻⁷; `scripts/conefor_check.py`, [Валидация](validation.html), раздел 6); с Graphab, Linkage Mapper и Circuitscape сравнения не было. Формулы сверены с первоисточниками, ответы — с аналитическими примерами и с независимой эталонной реализацией (`reference.py`). Реальные скачивания WorldCover / Copernicus DEM / Overpass из окружения разработки не запускались (сеть закрыта), загрузчик проверен на синтетических тайлах и подложном Overpass.

## 2. Что остаётся ограничением (не исправлено)

1. **PC / IIC / MESH не зависят от сопротивления.** *(Частично устранено в 0.2.0: добавлены PC и ECA по стоимости, раздел 5.5 методики; прямые индексы остаются инвариантными.)* Расстояния между патчами евклидовы. Поэтому сценарий «Восстановление пойм» даёт ΔPC = 0, хотя стоимость коридоров заметно падает; то же при любых весах поверхности (проверено скриптом чувствительности: CV PC = 0 %). Для оценки проницаемости ландшафта индексы нужно считать на *эффективных* (cost-weighted) расстояниях, как в Graphab и в Conefor с расстояниями по наименьшей стоимости. В интерфейсе сравнения сценариев это теперь прямо сказано. *Рекомендация:* добавить режим `distance="cost"` для PC (множественный Дейкстра от каждого из N крупнейших патчей; ограничение по числу патчей нужно из-за стоимости).
2. **Least-cost path — это один оптимальный путь.** Он не отражает множественность путей и случайное блуждание; теория цепей (McRae et al. 2008) и Circuitscape дают карту вероятной интенсивности движения и настоящие «pinch points». «Узкие места» в программе — эвристика (поток / локальная ширина коридора), а не результат анализа на токах; в тексте это теперь написано. *Рекомендация:* подключить расчёт токов (Circuitscape) для небольших кадров или хотя бы сравнивать с Linkage Mapper (Pinchpoint Mapper).
3. **Коридор — это путь + буфер заданной ширины**, а не коридор в смысле Linkage Mapper (полоса, где cost-weighted расстояние ≤ LCP + допуск). Ширина — параметр пользователя, не следует из биологии вида.
4. **Сопротивления классов экспертные и не откалиброваны.** Это главный источник неопределённости в подобных моделях (Beier et al. 2009; Zeller et al. 2012 — сравнение методов калибровки по данным о перемещениях). Скрипт `scripts/sensitivity.py` показывает, насколько результат зависит от этих чисел (см. п. 3). *Рекомендация:* калибровать по GPS-трекам / генетическим данным, когда они есть; иначе показывать результат как «сценарное сравнение», как сейчас написано в приложении.
5. **Видоспецифичность.** Один набор сопротивлений и одно d₀ для всех. Связность определяется для вида; реальный анализ требует задать фокусный вид (или группу), его d₀, минимальную площадь ядра и сопротивления.
6. **Ядра из OSM.** ООПТ из OpenStreetMap выбраны по тегам `boundary=protected_area` (классы IUCN Ia–IV) и `leisure=nature_reserve`; полнота зависит от картографирования региона. Если ООПТ не найдено, берутся крупные лесные массивы по WorldCover — это допущение, а не данные о местообитании вида; приложение предупреждает об этом (`warnings`).
7. **Точность входных данных.** По валидации ESA WorldCover 10 m 2021 v200 общая точность около 76,7 %; на уровне отдельных классов ошибки больше. Дороги и застройка из OSM неполны в малонаселённых районах. DEM Copernicus GLO-30 — модель поверхности (DSM), в лесу уклон может быть искажён.
8. **Разрешение и проекция.** Кадр ограничен 15 000 км² и ~700 000 ячеек; при 100–200 м ячейке тонкие барьеры (узкие дороги, 10–30 м) попадают в растр лишь частично — дорога прожигается в классе «дорога» шириной в ячейку. Для проектных решений требуется разрешение, соизмеримое с шириной барьеров.
9. **Нет учёта временной динамики и численности популяций.** Индексы — структурные, они не прогнозируют выживаемость.

## 3. Чувствительность к сопротивлениям (демо «Синий Бор»)

`python scripts/sensitivity.py --n 20` (сопротивления классов × exp(N(0; 0,5)), веса поверхности × U(0,5; 1,5)):

* Остов сети (MST): среднее Jaccard с базовым 0,97, минимум 0,50. Одна связь (0–1) выпадала в 5 % прогонов.
* Положение коридоров (пересечение / объединение полос шириной коридора): в среднем 0,45, минимум 0,25. Конкретные трассы чувствительны к сопротивлениям, и их нельзя считать устойчивым результатом без калибровки.
* Стоимость сети: коэффициент вариации 14 %.
* PC, MESH, IIC на прямых расстояниях: не меняются (см. п. 2.1). PC по стоимости: среднее 0,175 ± 0,005 (CV 3 %), порядок сценариев по ΔPC (urban < road < restore) сохраняется в 100 % прогонов; эффект «Восстановления» +14…+28 %.

Число прогонов невелико (20), это оценка порядка величины, а не доверительные интервалы.
