# Воспроизводимость

Цель: другой исследователь (или вы через год) может получить те же числа из тех же входных данных. Ниже — что для этого нужно и что программа делает сама.

## 1. Окружение

* Python ≥ 3.10; зависимости описаны в `pyproject.toml` (расчёт — основной список, тесты и сборка сайта — extra `dev`).
* Версии библиотек, использованные при сборке сайта, записываются в `provenance.json` рядом с демо (numpy, scipy, rasterio, и т. д.), там же — хеш коммита.
* Для точной фиксации окружения сохраните `pip freeze > environment.lock.txt` вместе с результатами.

## 2. Детерминизм

* Конвейер расчёта (поверхность сопротивления, пути, индексы, коридоры) **детерминирован**: случайность не используется.
* Единственный стохастический блок — анализ чувствительности (`scripts/sensitivity.py`); у него задаётся зерно (`--seed`), по умолчанию фиксированное. Одинаковое зерно и одинаковые версии numpy дают одинаковые розыгрыши.
* Возможны малые расхождения в последних знаках при смене версий BLAS/SciPy или платформы; сравнивайте числа с допуском (≈ 1e-9 относительно).

## 3. Идентификаторы и кэш

* **Токен результата** — первые 16 символов sha1 от (идентификатор проекта, сценарий, параметры); одинаковые входные данные → одинаковый токен, и повторный расчёт не нужен.
* **Идентификатор территории** — отпечаток запроса (границы, разрешение, настройки ядер).
* **Кэш** — каталог `data/cache/` (переопределяется переменной `ECOCORRIDOR_CACHE`): сырые тайлы, разобранные векторные данные и готовый проект. Повторный запрос идёт с диска без сети.
* URL источников можно переопределить через переменные окружения (шаблоны адресов тайлов и зеркала Overpass) — например, чтобы работать с локальной копией данных.

## 4. Как повторить расчёт

```bash
git clone https://github.com/DmitryLeLeE/eco_corridor && cd eco_corridor
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
python -m pytest -q                       # 50 тестов
python scripts/make_demo_data.py          # демо-полигон
python scripts/sensitivity.py --json out.json   # анализ чувствительности
python scripts/build_pages.py             # этот сайт
uvicorn ecocorridor.api:app               # приложение
```

## 5. Что сохранять при публикации результатов

1. Коммит (или релиз) программы и `environment.lock.txt`.
2. Каталог кэша территории (`meta.json` + растры) либо хотя бы `meta.json` с границами, датой загрузки и версиями источников.
3. Параметры сценариев и токены результатов.
4. Экспорт из интерфейса (GeoJSON коридоров, таблица индексов).
5. Дату загрузки OSM: эти данные меняются ежедневно.

## 6. Известные ограничения воспроизводимости

* Данные OSM не версионируются в программе: повторная загрузка спустя месяцы даст другой результат. Решение — хранить кэш.
* Ссылки на облачные тайлы могут измениться; источники и шаблоны вынесены в настройки.
* Для изолированного запуска есть `Dockerfile` (образ не публикуется; собирается локально).
